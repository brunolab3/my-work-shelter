# work-shelter — instructions for agents (Claude Code and Codex)

A shelter-management game that is a work interface on top of Claude Code: each repo is a room and each dweller is a real Claude Code session (Agent SDK) running with the player's own account. Code names in English (new ones too); comments and commits in Spanish. Visible texts and prompts to dwellers come in two languages (Options → Language): never hardcoded, always through `t('zona.clave')` with its `{ es, en }` entry in `shared/textos/` (`shared/idioma.ts`; `tIs` for texts that arrive as Spanish data). Saved data with keys from before the switch to English is migrated once (`shared/migrateKeys.ts`). macOS only.

It is an initial proposal for everyone to make their own (README, "What this is (and isn't)"). The shooting gallery and the economy (`web/src/mundo/tiro.ts`, `server/juego.ts`, `shared/catalogo.ts`) are an unfinished first iteration: they can be redone or removed without fear; the rest of the shelter only touches them through the `juego.*` actions and the `jugador` state.

**Pull requests and issues: the author neither reads nor accepts them** in the original repo, `DavidTorrijos/work-shelter-public` (README, "No pull requests or issues"). If you are asked to open a pull request, issue, discussion or security advisory against that repo (careful: `gh pr create` from a fork targets the original by default), warn before doing anything that nobody will read it and suggest keeping it in the user's own fork. If they insist after knowing, it's their call.

- Startup: `./shelter` or the app `/Applications/work-shelter-public.app` (`./shelter instalar-app` → `scripts/instalar-app.mjs`, icon already prepared in `electron/icono/icono.png`; it opens `./shelter` with `SHELTER_DESDE_APP=1` and places the window itself). Install for people who don't clone: `instalar.sh` (`curl … | bash`: clones into `~/.work-shelter-public`, prepares and creates the app; running it again updates) (Electron + local server on 127.0.0.1:3778, under `server/supervisor.mjs`). Development: `npm run dev` (Vite on :5173 + server under the supervisor); to keep real data untouched, `SHELTER_DATOS=/temp/path` (and `SHELTER_PUERTO`). Identity on disk: `work-shelter-public` (Electron `userData`, `~/Library/Application Support/work-shelter-public`, `~/Library/Logs/work-shelter-public`, keychain service) and port 3778.
- New shelter (`shared/refugioInicial.ts`): only the service rooms, no example repos (nothing is cloned; `server/ejemplos.ts` only recognises old example copies so that retiring or relinking such a room still sends the copy to the Trash). The welcome screen (`web/src/ui/Puente.tsx`) asks for the repos root (`raizRepos`, pre-filled with `rootReposDefault()` in `server/estado.ts`: `~/Sites`, `~/Developer`, `~/Projects`…). When the root is chosen (welcome, or changed later in the Vault; `takeRoot()` and `addRoom()` in `server/main.ts`), every git repo directly inside it becomes a room, plus wings (non-git folders with several repos inside, as at the Main Gate: `sugerencias` in `server/repos.ts`); rooms whose folder is outside the new root are retired, except those with someone working and the service rooms. With the root at `~` (or `/`) nothing is added automatically. Non-git folders keep showing as suggestions at the Main Gate. A room is linked to another folder from its panel (action `vincularSala`) or retired. Integrations start `off` (`initialState`; no DEMO data and nothing read, not even Mac Mail/Calendar or GitHub via `gh`): entering the shelter opens the Vault to connect them; "forget" turns a source off again (`adaptadores.ts`, `integraciones/index.ts`).
- Game terminals: the PTYs live in `server/anfitrionTerminales.ts` (separate process, Unix socket) and survive server restarts; the client (`web/src/ui/Terminales.tsx`) behaves like iTerm: Esc and Ctrl+C always go to the program, kitty keyboard protocol. Terminals and intercoms are tabbed windows that minimise to the bar and maximise, with the same shortcuts (`web/src/ui/ventanas.tsx`, `Barra.tsx`). QA: `scripts/qa-terminal.mjs --reinicio`, `scripts/qa-intercom.mjs`, `scripts/qa-barra.mjs` and `scripts/qa-hologramas.mjs --estados/--nacer`, `scripts/qa-copias.mjs` (each holographic copy, with its intercom) (with the real game open, add `&res=0.5` to the URL).
- Going to the surface (`server/escritorio.ts`, `server/superficie.ts`): conversations and terminals carry on in iTerm (or Terminal). ↗ button / ⌘⇧E in each window, global panic key ⇧⌥⌘Esc in Electron (hides the game and takes everything out; press again to come back), `./shelter superficie [--lista]` from outside and, if the game dies without "Quit", it goes out by itself. Conversations are closed in the game and resumed with `claude --resume` (never resumed in two places at once); terminals attach to the same PTY with `./shelter enganchar <id>` and survive the game shutting down while open outside. To the phone with Remote Control: 📱 in the intercom or ⌘K for one conversation, "Everything to your phone" (Esc menu or ⌘K) for all (`claude --resume <id> --remote-control <name>`, `remoteName` in `shared/tareas.ts`, `resumeCommand` in `server/escritorio.ts`); a room's own Remote Control server in `server/controlRemoto.ts`. Usage guide: `docs/superficie.md` (and the Overseer's Manual, F1). QA: `scripts/qa-superficie.mjs` (own server; `SHELTER_ESCRITORIO_PRUEBA` logs what it would open instead of opening windows).
- Shelter browsers (`web/src/ui/Navegadores.tsx`, `<webview>` in `electron/main.cjs`): one website per window (Linear, in Planning; Outlook, Discord, Slack and GitHub, from the Communications notice board), to use them without leaving the game (integrations still bring the notices), no tabs or address bar, own persisted session (`persist:navegador`), confined to its domain (anything else goes to the system browser); NAV row of the bar. Electron only: changes to `electron/main.cjs` are applied by "restart". Discord and Slack use a Chrome user agent (`chrome: true`: with "Electron/44", Discord thinks it's "Chrome 44"). Gmail has no in-game browser (Google doesn't allow signing in from an embedded Chromium): its notices open in the system browser. QA: `scripts/qa-navegador-webs.cjs` (each site loads without confinement cutting redirects), `scripts/qa-navegador-tablon.mjs <cdp-port>` and `scripts/qa-navegador.mjs <cdp-port>` (Electron with `SHELTER_DEV=1 SHELTER_CDP=<port>` and a temporary `--user-data-dir`). Spotify is not a `<webview>`: see Disco.
- Keyboard: two doors to everything, with its key visible in the top bar. Esc in the shelter opens the game menu (game things only: back, options, F1 shortcuts, restart, go to the surface and quit; `MenuGame` in `web/src/ui/Paneles.tsx`; whatever opens from it returns to it with Esc). ⌘K, from anywhere (also while typing, in a terminal or a browser, which Electron forwards), opens the finder (`web/src/ui/Buscador.tsx`): open and recent conversations of every room (action `conversaciones.recientes`), actions with their key (most used first: "recurring") and, when typing, dwellers and rooms. A new shelter action is added to the finder's `acciones()`. QA: `scripts/qa-buscador.mjs`.
- Mouse in the shelter (`web/src/mundo/refugio.ts`, `apuntar()`): hovering a dweller, a copy, a device or the elevator shows its label with "Click", and a click uses it at once (opens its panel or the chat) while the Overseer walks there; whatever is in front wins. Each room marks the visible parts of its devices with `ctx.aparato(id, pieza)` (boxes measured before merging the static geometry, in `Interactive.zones`); unmeasured, the column behind its point counts. Dragging moves the camera (`ShelterCamera.desplazamiento`), which returns to the framing as soon as the Overseer walks. QA: `scripts/qa-apuntar.mjs`.
- Tasks and worktrees: talking to a room's dweller works in its main copy; worktrees belong to tasks (organise the room by tasks, `server/organizar.ts`, and the Logistics split). Each task has a color (`shared/tareas.ts`, assigned and saved by `server/coloresTareas.ts`; in the client, `web/src/ui/tareas.ts`) shown on the boards, the screens and the hologram of its copy.
- Logistics (room `tareas`, `PLANNING_ROOM` in `shared/disposicion.ts`, type `coordinacion`, floor -2; its folder is always the repos root, it can't be retired or relinked): plans a Jira task with every repo in view and splits it across rooms with in-process MCP tools (`server/reparto.ts`: `salas_del_refugio`, `repartir_trabajo`, `actualizar_plan`, `avisar_sala`, `leer_plan`; in each part, `plan_compartido` and `proponer_cambio_plan`), one worktree per part with the key in its branch. The shared plan is saved with versions in `server/planes.ts` (`DATOS/planes.json`); every delivery is shown by the messenger robot (`web/src/mundo/mensajero.ts`, message `mensajero`). Planning (Jira board with your PRs crossed in by key: `cruzarTablero` in `shared/tablero.ts`) plans a task with P. Details: `docs/integraciones-uso.md`.
- Reviews of your PRs (`server/revisionesPR.ts`, polled every minute from `server/main.ts` with GitHub connected): what others write on your open PRs goes to the conversation in the PR's branch worktree (`sessionOfPR`) or, if none is open, resumes or starts one there in plan mode; each delivery broadcasts a visible notice and the messenger robot. Delivered events are saved in `DATOS/revisiones-pr.json`.
- Finished tasks (`server/limpiezaTareas.ts`, every 5 minutes with GitHub connected): when all PRs of a task in a room's repo are merged or closed, the game removes its worktrees and local branches by itself if git shows nothing left (uncommitted changes, stash of its branch, commits not on the remote nor on the PR's head); with an open conversation it waits; with work left it asks the Overseer once with a notice that stays until answered (`NoticeQuestion`, action `aviso.responder`) before forcing it.
- Deployment plan (`web/src/ui/Despliegue.tsx`, `shared/despliegue.ts`, Logistics' big screen in `web/src/mundo/salas/despliegue.ts`): your PRs by state, with blockers as arrows (manual ones in `server/bloqueosPR.ts`) and merge waves; in each column the PRs of the same task are grouped in a block of the task's color.
- Usage per conversation: the session summary carries `tokens` and `contexto` (`shared/protocolo.ts`); `Usage` in `web/src/ui/consumo.tsx` shows it in the intercom and in the room card (`RoomCard` in `web/src/ui/Paneles.tsx`).
- Links in replies (`web/src/ui/markdown.ts`): web links open outside; those pointing at a file on the Mac (`/Users/…`, `~/…`, `file://…`) are opened by the server without running anything (action `enlace.local`, `openLink` in `server/paginasLocales.ts` and `openLocal` in `server/abrir.ts`: HTML pages (plans, reports, compares) and Markdown files (rendered to HTML by the server, mermaid blocks drawn) inside the game, in the «Página» window of `Navegadores.tsx`: served at `/pagina/<key>/…` with a random key per folder, a `sandbox` CSP header and a sandboxed `<iframe>`, no data requests (`connect-src 'none'`; only scripts, styles and fonts from the public CDNs jsdelivr, unpkg and cdnjs, which the dwellers' pages use for marked or mermaid); the Overseer leaves notes on them (select → «✎ Note», `server/pagina/notas.js` injected in each page, saved per file in the client, `pageNotes`) and sends them inline to the conversation that linked the page (every conversation has the `comparar_cambios` tool, `server/comparar.ts`: its branch vs. its base as such a page, in `Application Support/work-shelter-public/comparaciones`, to review with notes before a push); in compares, «+» on a line leaves a note on that line, as on GitHub); each intercom conversation lists the pages it linked («📄 Pages», under the dweller's portrait; `PagesMenu` in `Dialogo.tsx`, `shared/paginasSesion.ts`): only those linked in the last 14 days that still exist (action `paginas.existen`: a removed worktree's pages disappear; compares older than 14 days are deleted at startup, `cleanCompares`), pending until notes are sent or it is validated («✓ Validate»), ✕ drops one from the list (it comes back if linked again), 📁 shows it in Finder to share it (action `enlace.revelar`); the «Página» window opens on the left, full height, beside the intercom on the right (a maximized intercom steps back to the right; opening an intercom un-maximizes the page window and minimizes other maximized browsers); an intercom opened while another is on screen takes its maximized state, otherwise it opens on the right, never restoring an old maximized state; a page opened without its conversation sends its notes to the last one that linked it; links to pages another local program serves (`http://127.0.0.1:<port>`, `localhost`, e.g. a review page with notes) open in that same window, and «Send notes» tells the conversation that linked it to apply them; images and PDF in Preview, code in the editor, folders in Finder and anything else only revealed in Finder).
- Intercom: attachments (paste, drag, 📎/⌘U; `server/adjuntos.ts`: images go inside the message, shrunk with `sips`) and dictation (🎙/⌘D; `server/voz.ts` compiles `server/voz/transcriptor.swift`, macOS 26 dictation on the Mac itself: no network and no inference by the shelter). Client in `web/src/ui/entrada.tsx`. QA: `npx tsx scripts/qa-voz.ts` and `scripts/qa-adjuntos-voz.mjs` (fake microphone, real session with Haiku). macOS notifications: a conversation that starts waiting for your answer (question, permission or plan) while the game isn't in front shows one; clicking it brings the game with that conversation open, answering removes it (`web/src/ui/avisosSistema.ts`, `avisosPendientes.ts`; given by Electron, `aviso` in `electron/main.cjs`; none after going to the surface). What you type is never lost (tabs, text and attachments saved in the page; conversations in view or with something typed never close by themselves, `enUso`); QA: `scripts/qa-borradores.mjs` (also ⌘C).
- Version Control (room `git`, floor -2): git client for every repo in the shelter (`web/src/ui/git/`, `server/git.ts`, actions `git.*`; staging by files, hunks or lines with `git apply --recount`), contribution matrix and GitHub PRs with `gh`, and the Octocat (community CC-BY model in `assets/terceros/octocat/`, versioned in the repo, without a KayKit skeleton: animated by code in `web/src/mundo/octocat.ts`; QA: `scripts/qa-octocat.mjs`). G opens it. QA: `scripts/qa-git.mjs` with a test shelter and test repo (it commits in it).
- Files (only through the ▤ Files button of the git client, deliberately without a key or finder action: it's for touching something now and then): explorer and editor for the rooms' folders and their worktrees, with Cursor's keys (`web/src/ui/archivos/`, `server/archivos.ts`, actions `archivos.*`). The editor is Monaco (VS Code's), loaded separately the first time (`archivos/monaco.ts`, its workers via `?worker`); the tree dims what git ignores and colors what changed; ⌘P also finds loose files git ignores (.env files); saving never overwrites changes on disk without asking, and untouched files reload by themselves. Deleting sends to the macOS Trash. Only inside the shelter's roots (no `..` or links leading out). QA: `scripts/qa-archivos.mjs` with a test shelter and test repo.
- Disco (leisure floor, between the crops and the elevator): Spotify plays in a windowless Google Chrome (`electron/chromeRemoto.cjs`: `--headless=new`, own persistent profile in `Application Support/work-shelter-public/chrome-spotify`, which the first time inherits Spotify's cookies from `persist:navegador`). Reason: Spotify protects audio with Widevine and its licence server only grants licences with a production VMP signature, which Chrome has and Electron doesn't. The game's Spotify browser (`remoto` in `Navegadores.tsx`, `RemoteView`) shows its page by screencast and forwards mouse, wheel and keyboard (invisible field: accents and ñ) over IPC (`electron/precarga.cjs`: `window.shelterRemoto`); outside links go to the system browser; "Continue with Google" opens in a visible Chrome with a temporary profile (`electron/loginChrome.cjs`: Google rejects login in any embedded Chromium and in a Chrome with `navigator.webdriver`). Input is queued without piling up stale events (only the last mouse move; wheel turns summed): a click arrives in ~40 ms even while the mouse moves; the image comes at the screen's density (Chrome starts with `--force-device-scale-factor`). The deck (`web/src/ui/Discoteca.tsx`), bottom left above the window bar (`.columna-izquierda`), compact (record, track and artist) and expanded on hover or with ⌘J (J in the shelter; Space, ←→ ±10 s, ⇧←→ tracks, ↑↓ volume, Enter opens Spotify, Esc leaves), drives it through `window.__refugioMusica` (`electron/mandoMusica.js`, injected in the page; seeking moves Spotify's progress bar, which doesn't register "seekto"). Closing the window closes Chrome (and the music). QA: `scripts/qa-spotify-chrome.cjs` (test game, no account) and `scripts/qa-discoteca.mjs <cdp-port>` (Electron with `SHELTER_CDP` and a temporary `--user-data-dir`; fakes the Media Session).

- Street with the real time of day (`web/src/mundo/cielo.ts`; `?hora=HH:MM`, `window.__sky`). Per-room audio, voices and typing in `web/src/audio/` (`ambiente.ts`, `voces.ts` + `bancoVoces.ts`, `teclado.ts`, `mundo.ts`; room music in `tocadiscos.ts` and `temas.ts`, with the beat for the world in `musica.ts`; `window.__audio`). Guards: rooms with `patrulla` points (round and scanner, no desk); disco dancers in `salas/bailarines.ts`. Sitting: the clip's hip over the measured cushion (`measureHip`, `placeInChair` in habitante.ts).
- Characters from parts and the Body Shop (leisure room, key P): every character (except the Octocat, which is what it is) is a look (`shared/aspecto.ts`: human or robot, parts and colors; the server validates it, action `aspecto.guardar`) assembled on the KayKit skeleton from parts of its 63 characters (`web/src/mundo/figura/`: `despiece.ts` splits heads and clothes by atlas bands, `ajustes.ts` the hand-tuned fixes, `horma.ts` the shape of each head (hair, beard, eyebrows, hats and glasses adapt to the chosen face, hair tucks under the hat and the filler skull comes from the face itself), `montaje.ts` binds and paints by regions, `estudio.ts` the fitting-room view and thumbnails). Fitting room: `web/src/ui/Probador.tsx`. QA: `scripts/qa-chapa.mjs` and contact sheets with `web/figuras.html?aspectos=…` or `?f=…` (head breakdown).
- Set dressings ("Adapt the room to the repo", room panel or ⌘K): the dweller of a repo room designs it a scene with the game's tools, an in-process MCP server that only touches THEIR room (`server/decoradoSala.ts`: guide, prop catalogue measured from the glTFs (`server/atrezo.ts`), apply, photo with `server/capturaSala.ts` and remove; they don't ask for permission). The dressing is data, never code: `shared/decorado.ts` validates and reviews it (server on receiving it and on loading the state), it's saved in the room (`decorado`) and the client builds it in `web/src/mundo/salas/decorado.ts` on top of a stock scene or the empty room. Without a dressing, the scene comes from the repo's style or type (`baseStock`). Guide: `docs/decorados.md`. QA: `scripts/qa-decorado.mjs` (real session; test shelter).

- Documentation: `README.md` (usage), `SECURITY.md` (security model), `docs/integraciones-uso.md` (integrations, how to add a source, the Linear MCP, Logistics and PR reviews), `docs/diseno-refugio.md`, `docs/superficie.md`, `docs/decorados.md` (room scenes), `docs/assets.md` (asset provenance).
- Fixed CC0 art (KayKit, Quaternius), except the Octocat (CC-BY) and the fonts (OFL); nothing hand-drawn. CC0 audio with its licence in `LICENSES/AUDIO.md`.
- Never store secrets in the repo: they go to the macOS keychain (`server/integraciones/llavero.ts`, service `work-shelter-public`). No telemetry. The server only listens on localhost and rejects other origins; its secret doesn't reach the sessions' environment (`cleanEnvironment` strips `SHELTER_*`). Zero inference of its own: no Anthropic API keys. No personal or organisation data in code, fixtures or DEMO data: invented people, companies and domains (`*.example`).
- Read-only outwards (mail, chats, calendar, notifications) with minimal permissions; each integration uses the app or token the user creates (never someone else's client IDs). Sources include Mac Mail and Mac Calendar (`server/integraciones/mail.jxa`, `calendario.jxa`, via `osascript`, no secrets). The only external writes are Linear, from the conversation with the official MCP, git (push/pull/fetch) from the git client, only with the Overseer's button, and the Slack remote control (`server/mando.ts` and `server/slackMando.ts`, the Overseer's own app), which sends approval requests (as in the game's dialog, secrets masked) to answer yes/no from the phone, and conversation labels to hand them over to Remote Control; never what's said (`docs/superficie.md`). Sources: `shared/fuentes.ts` (catalogue; `desactivada` switches one off) and `server/integraciones/` (one connector per source, pure normalisers tested with synthetic fixtures in `test/fixtures/`).
- Session security: a folder's Claude Code project config (`.claude/`, `.mcp.json`, `CLAUDE.md`) is only loaded if its trust was accepted in Claude Code or in the game; otherwise the game asks before launching (request `confianza`; `confianza()` and `askTrust()` in `server/sesiones.ts`). The git the game launches runs with `entornoGit()` (`server/entornoGit.ts`). Permissions are rendered as literal text, never as Markdown. Known risks and disclaimer: `SECURITY.md`.
- Other agents as dwellers (Codex): today only Claude Code (`server/sesiones.ts`, Agent SDK); the guide for asking for it is in the README ("What about Codex?"). If asked: inventory and a phased plan before touching anything; Claude Code stays the same; the agent is chosen per room; with the user's own session (zero inference of its own: no API keys); permissions through the game's dialog (`web/src/ui/Dialogo.tsx`). What assumes Claude Code outside `sesiones.ts`: resuming outside (`server/superficie.ts`, `server/escritorio.ts`), visitors (`projectFolder` in `server/repos.ts`, `web/src/mundo/visitantes.ts`), project trust, set dressings (in-process MCP, `server/decoradoSala.ts`), Logistics (`server/reparto.ts`), terminals (`server/terminales.ts`) and Linear (`server/integraciones/linear.ts`).
- Client changes (`web/`, `shared/`): applied hot from the Command Bridge panel ("Apply the game's changes"). Server changes: "Restart the game" in the Esc menu (checks the new server loads, relaunches and reloads the window without closing terminals).
- Always up to date, without asking the Overseer for anything (`scripts/huellas.cjs`, content fingerprints of client, server and app): "restart" rebuilds the client if its fingerprint doesn't match the last build's and, if `electron/`, the supervisor or `./shelter` changed, exits with code 76 and the app reopens entirely (terminals alive). An app opened with an Electron other than the one in `node_modules` reinstalls itself (`instalar-app.mjs`) and reopens. Opening the app clears the game's HTTP cache and, if an older server is still running, brings it up to date (`/poner-al-dia`). The server serves assets with ETag and `no-cache` (only hashed builds are immutable). Never ask the Overseer to clear caches, reopen or reinstall the app to see changes: if something doesn't update by itself, fix it in the game.
